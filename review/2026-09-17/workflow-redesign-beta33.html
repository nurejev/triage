1 · The corridor: seven doors, one order

Instead of nine always-visible destinations, the rail lists the seven steps in the order the work happens. Each has a gate (what must be true before it opens), a URL (so Back and reload work) and a status line (what happened there). A running collection locks everything after Collect.

2 · Sign-in: rows on Connect, reused on Respond

The proposal's complaint was four browser windows announced only by a status line. As built, every window belongs to a row that says it will open, shows a waiting state with elapsed time, and shows the result. On the web that is one window per case (plus consent when you arm containment); in the desktop app one per service, kept as a PowerShell session until Collect releases it.

3 · One screen per step

The real screens of build 33. Web frames run in a browser with the Connect sign-in; app frames show the desktop app with its service rows and PowerShell collector. Callouts name what the proposal asked for and where it landed.

The first 60 minutes

Twelve-minute windows: 0-12 triage and confirmation · 12-24 containment (the numbered steps below) · 24-36 blast radius · 36-48 evidence · 48-60 communication. The order of the containment steps is not arbitrary: resetting the password before revoking sessions leaves the attacker a window to add a recovery method with the token they already hold, and walk back in through the reset you just did.

0

Preserve the evidence before you change anything

manual

Remediation destroys evidence. The inbox rule you delete, the OAuth grant you revoke and the sign-in session you kill are all artefacts somebody will ask about later. Export first, then contain. Running triage on this account (or importing an extraction) gives you the sign-in and audit evidence in one JSON.

1

Revoke sign-in sessions

flagged by triageverification pending

First, because most compromises in 2025-2026 are token theft, not password theft. This invalidates the refresh tokens, so the stolen session cannot be renewed. Access tokens already issued stay valid until they expire (roughly an hour, less with Continuous Access Evaluation) - which is why this is the first step and not the only one.

PowerShell equivalent
Connect-MgGraph -Scopes "User.RevokeSessions.All","User.ReadWrite.All","UserAuthenticationMethod.ReadWrite.All","DelegatedPermissionGrant.ReadWrite.All"
Revoke-MgUserSignInSession -UserId jan.devries@contoso.nl
2

Disable the account

verification pending

Disable, never delete - deletion destroys the audit trail and is painful to undo. Disabling blocks new sign-ins and closes the access-token window for CAE-capable workloads. Re-enable only when containment is verified and the blast-radius list is finished, not when the user complains.

PowerShell equivalent
Update-MgUser -UserId jan.devries@contoso.nl -AccountEnabled:$false
3

Reset the password

verification pending

A throwaway password that breaks the attacker's hold - not the one the user types tomorrow. It is generated in this browser tab, shown once, and never sent anywhere but Microsoft Graph. The user sets their own through your controlled process when the account is re-enabled.

PowerShell equivalent
$passwordProfile = @{ ForceChangePasswordNextSignIn = $true; Password = $tempPwd }
Update-MgUser -UserId jan.devries@contoso.nl -PasswordProfile $passwordProfile
4

Review and strip authentication methods

verification pending

The step most people skip. If the attacker registered their own phone number, authenticator or passkey during their working window, the password reset hands the account straight back to them through self-service reset. List everything and remove what the user does not recognise. A method that is set as the default has to be replaced before it can be removed.

PowerShell equivalent
Get-MgUserAuthenticationMethod -UserId jan.devries@contoso.nl | Select-Object Id, AdditionalProperties
Remove-MgUserAuthenticationPhoneMethod -UserId jan.devries@contoso.nl -PhoneAuthenticationMethodId <id>
# also: Remove-MgUserAuthenticationMicrosoftAuthenticatorMethod / -Fido2Method /
#       -TemporaryAccessPassMethod / -SoftwareOathMethod / -EmailMethod

Get-MailboxPermission -Identity jan.devries@contoso.nl | Where-Object { $_.User -notlike 'NT AUTHORITY\SELF' -and $_.IsInherited -eq $false }

Remove-InboxRule -Mailbox jan.devries@contoso.nl -Identity '<rule name>'
Set-Mailbox jan.devries@contoso.nl -ForwardingAddress $null -ForwardingSmtpAddress $null -DeliverToMailboxAndForward $false
6

Revoke OAuth consent grants

verification pending

The silent one. A malicious application holding Mail.ReadWrite plus offline_access does not need the password or the session - revoking sessions does not touch it. Removing the grant stops new tokens being issued; tokens already issued live until they expire. Tenant-wide (admin-consented) grants do not show up in this per-user list - check Enterprise applications as well.

PowerShell equivalent
$userId = (Get-MgUser -Filter "userPrincipalName eq 'jan.devries@contoso.nl'").Id
Get-MgUserOAuth2PermissionGrant -UserId $userId | Select-Object Id,ClientId,Scope,ResourceId
Remove-MgOauth2PermissionGrant -OAuth2PermissionGrantId <grantId>

How Triage works.

Seven steps, one case. What each step needs, what it never does, and where the coverage limits are.

The seven steps

1
Start

New investigation, open a case, or practise on the sample.

2
Connect

Sign in once. The web uses your browser session; the desktop app signs each service in with PowerShell and keeps that session until you collect.

3
Scope

One account or the whole tenant, the window, and an evidence preset. A plan saved on the website opens in the app.

4
Collect

Progress and gaps on one screen. Stop keeps what was returned. Review opens by itself.

5
Review

Overview, findings, timeline and evidence. Findings and records open in a drawer; Back closes it.

6
Respond

The first 60 minutes in five phases. Arming containment asks for write permissions once, and says so first.

7
Hand over

Checklist, exports and the complete action log. Sending happens outside this workspace.

Your evidence

The case saves itself on this device (browser storage) while you work. Export a case file to move between the desktop app and the web viewer; import it on Start. Nothing is uploaded. Team upload is not configured in this beta.

Local validation does not establish live-tenant collection success. Native builds are development builds; signing and Windows acceptance are recorded separately in the validation guide.

Scope and completeness

  • User scope filters user events and mailbox data. Policies, groups, application permissions, alerts, licenses, managed identities and Azure activity remain tenant context. They are not automatically attributed to the affected user.
  • Tenant scope includes all accessible users/mailboxes. Access restrictions and individual source errors remain visible as gaps.
  • Browser queries have page limits (200 for volume sources, generally 50 for inventories); partial sources retain continuation metadata. Portable Graph follows pagination until exhaustion or an explicit error.
  • Message trace uses time slices and continuation, with a 90-day service window. Dedicated audit searches may hit service result limits; such results are partial. Retention and licensing still apply.
  • Current snapshots do not prove historical state. A complete query does not prove that Microsoft retained every event.
  • Cases are held in memory. Individual imports are limited to 100 MB; combined imports and native saved cases to 250 MB. Tenant-wide email and attachments may exceed this candidate’s limits; use narrower windows or deselect content sources.
  • Email uses the received-time window. Attachments preserve the API-returned payload. Reference/item attachments and MIME-level mail export are not certified equivalent to upstream email downloading. MailItemsAccessed records are preserved in UAL; a separate message/session extraction report is not yet provided.

Analyzer Suite comparison

Triage runs selected MAS-derived JavaScript checks for sign-ins, directory audit, UAL, identity risk, OAuth, users, devices, roles and MFA, plus its Exchange snapshot checks. The app and browser viewer run the same analysis on the same evidence.

Newly collected sources do not imply new detection coverage. Message trace and transport rules are readable evidence inventories; their upstream analyzers and spreadsheet/statistical reports are not reproduced in full. A rule-by-rule comparison, enrichment parity and identical upstream report output are still pending.

Permissions and connections

Delegated access or a customer application certificate may collect data. New source permissions require admin consent and applicable service roles; a saved registration is not silently changed. Azure requires separate access to the subscriptions. Connection success does not guarantee that every source is readable. Response permissions are separate and requested only for explicitly armed actions.

Native response bridges Graph account actions. The first-hour mailbox card runs local read-only collection; Exchange changes currently use its manual PowerShell steps. Collection certificates remain read-only.

4 · The navigation contract, as built

The rules the proposal asked for, with where each one lives now.

  1. The rail is the map.Seven steps in order, one status line each, ticks for done, grey with a reason for not yet open (renderRail(), stepStatus(), gateFor()).
  2. The URL names the step and the case.#/start … #/case/<id>/review/findings?f=…. Back returns to the previous screen or closes the drawer; reload lands on the same screen of the same case (navigate(), rememberRoute()).
  3. One primary action per screen.New investigation · Choose the scope · Start collection · Open Review · Save review · Next phase · Hand over. Secondary actions are text buttons or sit in the case bar.
  4. Sign-in happens on Connect, nowhere else.Web: tenant pinned, one window. App: one row per service, session kept. Scope and Collect never open a window; Respond reuses the sign-in (web) or announces its one window (app).
  5. Details open beside the list.Findings, records and sources open in a drawer (.drawer-layout) that keeps the list's scroll, filter and severity. No modal, no jump to another page.
  6. A running collection locks the rest.Review, Respond and Hand over show Collection is running; the rail shows the running collection with Stop; Review opens by itself when it ends (finishCollection()).
  7. The case saves itself and says so.1.5 s after a change: IndexedDB on the web, the evidence folder in the app. The case bar shows saving… / saved hh:mm; leaving warns only while collecting or unsaved (touch(), autosave()).
  8. Collect states whose evidence it is.Account or whole tenant, tenant, window, sources, method, signed-in analyst — in a banner, not a small row; it stays after the collection and on reopened cases (collectionTarget(), build 33).
  9. A second collection asks first.Start a new collection? keeps the open case saved under Open a case; the sample is discarded silently because it is never saved.
  10. Every change is visible as a build number.BETA badge, footer Build n · Guide, Help → What's new (build.js); the live site has its own build number for shared files.
