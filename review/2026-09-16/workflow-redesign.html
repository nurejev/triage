1 · Today: nine doors, no corridor

The sidebar (desk.js:83-93) shows all nine destinations from the first second; six of them render an empty state until a case exists. The real navigation happens through buttons inside dialogs and cards — and five of those hops land somewhere the person did not expect. Nothing is in the URL, so the browser's Back button leaves the site.

2 · Sign-in: four browser windows, no screen for them

In the desktop app, delegated sign-in still happens inside PowerShell (collect.ps1:112 and :185, response.ps1:13). The browser opens by itself; the app shows one line of status text on the Overview page. The target makes every prompt a row on the Connect screen — button, waiting state with elapsed time, result — and reuses the session for Respond. The msal-node hand-off (WP-41) then removes windows without changing the screen.

3 · Target: seven steps, one rail

Steps 1–4 are a wizard: one screen each, Back and Next. Steps 5 and 6 are working areas with tabs inside them — the Review views and the five first-hour phases that already exist. Step 7 is a checklist with the exports. Web and app differ only on Connect and Scope; from Collect onward the screens and the case file are identical.

5 · The navigation contract

Ten rules every screen obeys. The work package references them by number.

  1. The rail is on every screen.Current step highlighted; future steps disabled with the reason on hover; completed steps navigate back, with a warning when that discards a collection.
  2. One primary button per screen.The step's exit. One Back. Everything else is secondary or a text link.
  3. State lives in the URL hash.Back, Forward and reload work; reload restores the case from autosave. Electron keeps will-navigate denied; trusted() compares origin + path.
  4. Dialogs never navigate.They confirm or collect a short form. No button inside a dialog changes the page under it.
  5. Details open in a drawer.A finding, a record, a rule. The drawer is a route (?f=, ?r=); closing it is Back; scroll position is kept.
  6. Sign-in happens on Connect only.The write step-up happens on Arm only. Both are rows: button, waiting state with elapsed time, result. Never a status line, never a side effect of another button.
  7. Autosave, and say so.Every case mutation is written (debounced) to IndexedDB on the web or the evidence folder in the app. The case chip shows Saved 12:04 or Unsaved changes; beforeunload warns only when unsaved.
  8. No empty pages.A step that cannot be shown yet is disabled, not rendered with an empty state.
  9. One header, both surfaces.Brand · rail · case chip · session chip (account · tenant · Graph/Exchange · Write) · theme. The static breadcrumb goes.
  10. Web and app differ on Connect and Scope only.How you sign in and which evidence exists. From Collect on, the screens and the case file are identical.
